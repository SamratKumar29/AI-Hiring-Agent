1. cd into career-ops/ inside your WSL project and run `npm install`. Then copy config/profile.example.yml to config/profile.yml and fill in your identity, target roles, and comp range.
2. Open the career-ops folder in Claude Code or Cline (whichever you're using in WSL) and run the intake mode (e.g. type '/career-ops intake' or ask it to run modes/intake.md). Point it at your existing resume — this generates cv.md and modes/_profile.md, which everything else scores against. Do this before anything else; nothing works well without it.
3. Export OPENAI_BASE_URL=https://openrouter.ai/api/v1, OPENAI_API_KEY=<your key>, and OPENAI_MODEL=<model id> in  a .env in career-ops/ as backup.
4. Open career-ops/data/pipeline.md, add lines under '## Pending' like: - [ ] https://boards.greenhouse.io/company/jobs/123 | Company | Role. Grab a couple of real postings from LinkedIn/Naukri/wherever manually. Then run '/career-ops pipeline' in Claude Code or Cline. This validates your whole setup (profile + LLM key + evaluation) without touching Supabase or the scrapers at all.
5. Check data/applications.md and reports/ for the scored, ranked results. If this step works, your core brain is functioning — everything else (scrapers, scheduling) is just additional ways of getting URLs into that same pipeline.md file.
6. Create a free Supabase project, run job-scraper/supabase_setup/init.sql, then integration/00_shared_jobs_table_migration.sql. Note the URL + service role key — you'll need them for job-scraper, ai-job-scraper, and sync-pipeline.mjs.
7. Bring anandanair/job-scraper online (local, on-demand)
In its venv: fill config.py (search queries, MIN_SALARY_USD), add SUPABASE_URL/KEY/LLM_API_KEY to .env, then run `python scraper.py` followed by `python score_jobs.py` whenever you want fresh LinkedIn results. These land straight in Supabase.
8. Sync Supabase into career-ops and run the full pipeline
cd career-ops, npm install @supabase/supabase-js, add the Supabase env vars, run `node sync-pipeline.mjs` to pull scraper results into data/pipeline.md, then `/career-ops pipeline` again — same as your manual test in step 4, just auto-populated now.
